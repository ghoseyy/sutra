# Content translation schema

`src/data/i18n/_src/<section>.json` is the English skeleton (generated by
`npm run i18n:extract` from `src/data/sections/*.json` — never hand-edit it).

Each translation file `src/data/i18n/<lang>/<section>.json` (lang = `ne` or `hi`) has the same
shape and MUST cover every id the skeleton has:

```json
{
  "section": "05-avatars",
  "nodes": {
    "<id>": {
      "name": "...",            // translated name, Devanagari script
      "aliases": ["...", "..."],   // same length/order as English, or [] if English is []
      "description": "...",
      "story": "...",
      "symbols": ["..."],
      "weapons": ["..."],
      "vahana": "..." | null,      // null only if English is null
      "abode": "..." | null,
      "sources": ["..."],          // text names may stay transliterated/untranslated
      "variations": ["..."]
    }
  },
  "edges": {
    "<source>|<target>|<type>": { "label": "...", "variation": "..." }  // variation only if English had one
  }
}
```

Rules:
- Translate `name`, `description`, `story`, `symbols`, `weapons`, `vahana`, `abode`,
  `variations`, and edge `label`/`variation` fully into natural, respectful **Nepali** (`ne`)
  or **Hindi** (`hi`), in Devanagari script — not a word-for-word gloss, but idiomatic prose
  a native reader would recognise as their language, not Sanskritized filler.
- `aliases` and `sources`: translate/transliterate but keep the same array length and order
  as the English skeleton (an empty array stays empty).
- Keep every proper name recognisable and consistent with how it is rendered elsewhere in the
  same file and, where you can check, in already-translated sections (e.g. रावण not रावन).
- Never invent content, drop nuance, or resolve a variation the English text left open.
- Every key in the skeleton's `nodes` and `edges` must be present in the output. Do not add
  ids that aren't in the skeleton.
- Output must be valid JSON (watch escaped quotes) and pass
  `node scripts/validate-i18n.mjs <lang> <section>`.
